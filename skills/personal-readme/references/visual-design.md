# Visual design

## Study a reference and extract a principle

Pick references for the audience and task. Compare hierarchy, scanning order, typical mobile crop, repetition, dependence on images, and what happens when an asset fails. Use a reference to justify a design choice in one sentence. Create original artwork and confirm permissions and attribution for reused assets.

- [GitSkins README Studio](https://www.gitskins.com/readme-builder) demonstrates audience-specific layout, editable Markdown, and theme-specific previews. Review the result as well as its source when available. Require direct evidence for generated labels or metrics. Keep projects and contact instructions readable when generated cards fail.
- [Awesome GitHub Profile README](https://github.com/abhisheknaiidu/awesome-github-profile-readme) offers a discovery index for editorial, technical, minimal, and expressive examples. Inspect the actual linked profiles before making decisions.
- [Understand Anything](https://github.com/Egonex-AI/Understand-Anything) demonstrates the use of a memorable visual hook tied to the work. Translate the underlying idea into original art.
- [Skill Icons](https://github.com/tandpfun/skill-icons), [Readme Typing SVG](https://github.com/DenverCoder1/readme-typing-svg), and [GitHub Readme Stats](https://github.com/anuraghazra/github-readme-stats) offer optional assets. Check current licenses, availability and hosting, and preserve equivalents in text.

## Design the original banner

Inspect the actual first screen on a phone-width preview. If the banner makes the primary project hard to find or sits between that project's main action and its supporting example, shorten it or move it to a natural section boundary. Preserve the visual identity in the new placement. Read the relevant block in sequence to verify that a visitor can move from description to action or proof without a visual detour.

Sketch two usable concepts. For each, specify the visual hook, relation to the developer's work, image technique, and narrow-screen behavior. Possible directions include a restrained editorial wordmark, a technical diagram or motif, and a playful original mascot interacting with a project idea. Use contrast, spacing and one clear focal point. Preserve existing visual anchors in a redesign where they still suit the goal.

For exact wording and typography, compose an editable SVG, or generate illustration and add type programmatically. In an image-generation prompt use only approved public information and visual assets. Generate subject, composition, and lighting deliberately. Keep meaningful details in a generous safe area. A practical starting aspect ratio is around 3:1, then inspect actual widths. Use text in the README for essential information, even when the banner depicts a name. If exact font rendering matters, embed no external font dependencies. Export a local PNG when consistency needs it. Keep short prompt/source notes where useful, excluding private inputs and unused drafts.

Use badges to communicate information a reader can act on, such as format or a verified release. Use project images when they show proof or explain the work. Keep each if its function still matters with animation disabled and on a narrow viewport. An animated accent is optional. Keep a static equivalent for the content it conveys and test the actual file size and fallback.

## Buttons, stack icons, and statistics

Link buttons to real actions or destinations. Keep labels accessible and check the image and destination, including section anchors. Prefer a short icon row using tools the developer has chosen or demonstrated. Keep local copies only where the license permits it and retain the required notices. When using supplied pet or terminal imagery as inspiration, draw original artwork and carry the identity through typography and color.

If the brief asks for statistics, choose a few public metrics with clear definitions. For a static snapshot, record the date and scope and link to the live source. For a dynamic card, check the actual image response and keep a native link or text fallback. Match the metric wording to its data source, especially for language percentages and contribution counts.
