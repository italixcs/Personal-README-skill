# Design research

**Recommendation.** Build a small profile design workflow. Reuse GitHub Markdown and existing asset tools. Profile generators already populate templates quickly. The uncovered work is selecting evidence, making editorial choices, preserving a developer’s public identity and proving the draft reads well with its real assets.

| Reference | Useful principle | Decision |
| --- | --- | --- |
| [GitSkins README Studio, Recruiter-ready](https://www.gitskins.com/readme-builder?username=italixcs&theme=github-dark&template=recruiter) | Personalized previews, a short identity and featured work, inspectable Markdown, and light/dark image variants. The observed preview inferred a role from public data, repeated metrics, and relied on hosted images for stats, projects, toolkit, and activity. | Preserve scan order and preview/source parity. Require evidence for labels, use local assets, and leave metrics optional. |
| [GitHub Profile README Generator](https://github.com/rahuldkjain/github-profile-readme-generator) | A form and Markdown export make predictable assembling quick. | Use as a fast option when a user already wants a standardized layout. Avoid replicating its form and template catalog. |
| [Awesome GitHub Profile README](https://github.com/abhisheknaiidu/awesome-github-profile-readme) and [Anurag Hazra](https://github.com/anuraghazra/anuraghazra) | A profile-specific header can express identity. Direct prose and working links carry the substance. | Keep a native H1 and readable project copy. Use image space for a recognizable visual. |
| [DenverCoder1](https://github.com/DenverCoder1) | Related tools provide a natural curation angle. | Feature a developer’s work by audience fit and use case. |
| [Understand Anything](https://github.com/Egonex-AI/Understand-Anything) | A project-specific mascot or graphic can make tools easier to remember. | Consider an original mascot or motif only when it illustrates work. |
| [Skill Icons](https://github.com/tandpfun/skill-icons), [Readme Typing SVG](https://github.com/DenverCoder1/readme-typing-svg), [GitHub Readme Stats](https://github.com/anuraghazra/github-readme-stats) | Icons compress a short technology list. Motion and stats can support a specific story, but add maintenance and availability dependencies. | Optional integrations. Active content stays native, and external widgets require fallback content. |
| [GitHub rendering guidance](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/quickstart-for-writing-on-github), [relative links](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax), and [GitHub Markup](https://github.com/github/markup) | GitHub supports targeted HTML such as a documented picture fallback, rewrites relative paths, and applies sanitizer and other processing steps. | Prefer native Markdown, simple local PNG or standalone SVG, and full fallbacks for theme variants or motion. Disclose limits of local previews. |
| [Repo Cleaner](https://github.com/italixcs/Repo-cleaner) | Trace purpose → proof → action. Caption artifacts accurately. | Reuse those principles and route repository-specific tasks to Repo Cleaner. Keep installation independent. |

No third-party code, artwork, templates, or statistics services are bundled. The GitHub documentation was also checked via Context7. The GitSkins preview and its Code view were observed directly in a browser. Account-gated exports were left unused.
